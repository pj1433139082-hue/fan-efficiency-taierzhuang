## 0. 三十秒背景

Excel 模板只借它的**公式结构**，数字全是示例。模型要算的是双口径：

```
修正口径：P_aero = (P_entry/K) × (Q_in/60) × [((P_entry+Δp)/P_entry)^K − 1]   η = P_aero / P_motor
Excel 口径：P_aero = (C18/1000) × (Q_std/60) × [((P_entry+Δp)/P_entry)^K − 1]   η = P_aero / P_motor
            C18 = P_标准/K = 354635.54，Q_std = Q_in × (P_entry/P_标准) × (T_标准/T_in)
```

**四条进展**（都会影响这份清单要问什么）：

1. **本期部署口径已定 = Excel 口径**（`eta_excel`），修正口径并列输出只用于对账。所以凡"只影响修正口径"的项一律降级。
2. **已用 18 个月 IoT 数据自己核过一批**——1,394 万条 15 s 原始记录折成 349.6 万个分钟格，见 §5，不用再问人。
3. **模型已建成（22 项测试通过）并已入库 GitHub 协作仓库**，效率侧现在缺的只有「口径确认」和「数据可用性确认」。
4. **下游「风机最优组合」模型对接后暴露出 3 个新问题**（§4）：效率下限依据、喘振边界、母管能否并联。这三条不改变单机效率数值，但**卡住下游上线**。
